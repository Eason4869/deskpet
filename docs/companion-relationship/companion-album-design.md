# 伙伴纪念册视觉修订 F3

用户在 2026-10-25 指定 frontend-design，要求角色面板进一步美化、更多图片表达、逻辑清晰，并明确欢迎语与纪念卡可以重新设计。本轮承接已通过审阅的 S2，不重做关系业务。以下方向由实现方根据当前截图和既有风格选择，实际界面仍交用户审核；不表示用户已经逐项确认设计参数。

## 方向与取舍

现有主页的问题不是缺少边框：左侧大块档案背景只放小头像，关系环比角色更抢眼；欢迎语附在保存按钮旁，缺乏自己的信息层次；800×480 卡片缩略后关键文字过小，六阶段几乎同一外观。

考虑三种方向：保留仪表板只增加图标（不能解决主次问题）；做全屏角色海报（占用过多空间，导入角色质量不稳定）；采用**伙伴纪念册**（本轮选择）。以真实角色图像为主视觉，以留言和纪念卡表达陪伴，关系数值作为清楚但不过度抢眼的辅助。保持现有蓝色应用外壳，不采用全新品牌字体、复杂动画或收藏游戏化任务。

## 视觉系统

- 颜色：浅页面 #FFFFFF、浅承托 #EDF3FF、强调蓝 #357FF5、主文字 #203754；深页面 #222832、深卡面 #2B3545。其余文字/边框沿用现有 Ink/Muted/CardBorder 对应主题。暖色仅可用于小面积纪念徽章，不能抢过角色。欢迎语和图片内部也必须深色适配。
- 字体：继续本应用中文及多语言回退字体，不安装新字体。角色名 26–28，区域标题 18–20，主要台词 16–18，正文 13–14，日期 12–13。不要用字距、全大写或虚构编号装饰。缩略卡的阶段名必须比装饰小字更醒目。
- 布局：内容最大约1080、宽屏边距28/窄屏16。头像与名字仍横排；长名字可折行或省略并提供完整可访问文字。图像使用 contain、不截角色头部和四肢。
- 原生矢量插画配合真实角色图片，装饰不进入键盘顺序，不绘制无数据意义的图表。避免六个区域全部套同一尺寸厚卡片。

```text
伙伴主页
┌ 真实角色形象 / 头像 + 名字 ─────┬ 我们的关系 / 当前阶段 ─────┐
│ 简短档案 / 可折叠介绍            │ 分数、差值、阶段序列        │
│ 当前阶段欢迎留言                │ 今日成长 / 相处 / 相识     │
└─────────────────────────────┴──────────────────────────┘
相伴纪念册                       相伴历程（宽屏紧凑侧栏）
┌ 插画纪念卡 ┐ ┌ 插画纪念卡 ┐    已保存日期与阶段
│ 阶段、日期 │ │ 阶段、日期 │    真实阶段欢迎语可回看
└ 预览 / 保存┘ └ 预览 / 保存┘
成长规则 / 关系设置（原有折叠入口）
```

窄屏依次显示档案/留言、关系、纪念卡、历程、规则设置；不出现横向滚动。主页必须在合理滚动距离内找到规则和设置，不能用巨大海报挤掉操作。

## 三处重点设计

### 1. 角色与留言

使用当前伙伴自身的高清 preview 或现有静态 idle 帧，优先复用已验证的资源加载链。WPF 可沿用 SkinCatalog.GetPreview；Avalonia 可复用 SpriteAssets 的 Preview/idle 帧及现有原生绘制方式。不能为导入角色误用 E 包的配图。缺失/损坏图像回退到该伙伴现有头像；若头像也不可读则使用中性占位，不能使整页失效。静态展示不新增播放计时器或循环动画，避免持续 CPU/磁盘开销。图像资源生命周期和同伙伴换装刷新沿用 S2。

角色形象约180–230高，档案头仍保留56–72头像及右侧名字。与留言和关系卡形成一个完整的顶部区域，不能留下旧版空置大色块。深浅主题均保持原色人物。

这里的高度以可见角色轮廓为准，不能把带大块透明留白的480×520源图简单缩小后仍只剩小人物。可在静态加载时计算透明外边界并对显示源矩形做contain，留少量安全边距，不裁去实际不透明像素，不修改原资产。无透明图使用完整图，空图进入回退。计算与图像只在来源变化时缓存一次，不逐帧扫描。

**欢迎语**独立为角色留言区域：小型引号或信封矢量、阶段标签、足够字号的完整台词。内容来自当前已保存阶段的 RelationshipContent 欢迎语，回看里程碑时仍能看到对应阶段内容，不虚构 AI 对话、情绪或经历。不把欢迎语和纪念卡的保存按钮挤在同一段落。长角色台词需折叠/展开且可键盘访问，保留全文；空/读取失败时只显示真实可用内容，不推断已解锁。

### 2. 新纪念卡

保持 PNG **800×480**，重新设计内部构图：角色图像占约左侧42%，置于有边距的矩形肖像区；右侧为醒目的阶段名、伙伴名和真实达成日期。足够大的文字区域，不缩小到无法辨认，不用斜置卡片或裁剪伪装美感。2026-10-25 用户明确否定首稿的装饰圆圈，禁止角色周围圆环、卡面穿过人物的圆弧、无信息意义的星形/几何装饰。

六阶段采用统一肖像与文字构图，通过真实阶段标题和可读的日期区分；不再强制添加六种几何徽章。阶段名称、日期才是语义，不增加新的游戏等级、奖励或规则。已解锁状态只取保存记录；不得生成带虚假达成日期的未解锁卡。先做好人物比例和排版，不以更多装饰替代设计。

深色 PNG 底色 #2B3545 与页面 #222832 区别清楚，文字及装饰分别校准。浅色保持清洁蓝白。预览、缩略图、展开及导出仍使用同一份冻结数据和同一 PNG 字节，身份/主题/locale/装扮变化令缓存失效，保存对话框期间不串图。固定PNG保持名字、阶段、日期可读；超长姓名可省略，但完整姓名在页内及可访问信息仍可取得，长德语日期不得覆盖操作或跑出图像。

不引入外部图像依赖或新下载流程；优先原生绘制既有角色图片与矢量图案。无需为布局生成整张位图截图，更不把演示图作为运行界面。

### 3. 关系与回顾

保留真实分数、下一阶段差值、六阶段顺序、今日6/20、有效相处天数、相识天数，但降低仪表盘感。圆环替换为约5px的细进度条，六阶段用有文字的短线刻度，不增加第二套业务计算；不同阶段状态不能只靠颜色。纪念卡与日期历程要有明确标题，重复的日期或标签只在有助理解的位置展示。错误/保存中/日上限/暂停/最高阶段继续靠近关系区，原有重试、打开目录及重启入口不消失。

## 不变约束与验收

- 不修改计分、身份、存储、解锁、反馈免打扰或AI上下文规则；不实现心情/衣柜收藏/故事等后续功能。继续从现有保存结果构建页面。
- 保留S2实际滚动、展开、按阶段恢复焦点、同ID换装刷新、PNG一致性与无预览落盘保障。静态图像不得触发互动计分。
- 两端同样的信息顺序、图案和主题层次；WPF现有实际最窄520，Avalonia390，不提高下限掩盖溢出。长语言、长姓名、长欢迎语、损坏preview、零分/最高阶段/错误均需验证。
- 新文案13语言、字面量camelCase资源键；既有全分支本地化门禁仍由M6处理，不借本轮改写审计规则。
- 交付实际浅深宽窄截图、欢迎语展开、六阶段导出卡图及导入角色/异常图回退证据。区分WPF非活动桌面、Avalonia Windows无头与未做的macOS硬件验收。沿用独立用户目录，不操作用户桌面/真实安装/真实资料，不做MSI或上游发布。

## 构建检查后的具体边界

- Avalonia不存在PetSkin版GetPreview：使用skin.Preview与assets.Get，或Resolve idle + Rect；异常回退须在构建静态画面时完成，不能把读取失败留到Render抛出。preview、idle、avatar各自都可能失败。
- SpriteAssets可能淘汰并Dispose缓存图片。静态图像必须有明确所有权或及时取回，不能跨来源切换保留可能已销毁的借用Bitmap。HomeCardCapture的PNG图像生命周期不改变。
- StageName/DateText是实时本地化getter，创建卡面时一次捕获文案、主题和图像来源。相同伙伴换装/资源更新不能继续用旧图；保存窗口打开期间继续使用该次PNG。
- State==null时不能把零分投影当成真实已保存阶段，阶段欢迎语不显示；有缓存保存结果的读失败可保留留言并同时明确警告。
- 纪念卡每列可用宽度至少约320–340才并排，按实际容器计算；不足时单列。固定PNG文字区有明确边界与长文本策略，不使用无界StackPanel排版。必要的阶段/日期在图片外有可读原生文字。
