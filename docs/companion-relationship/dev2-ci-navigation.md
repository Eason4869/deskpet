# 0.11.2-dev.2 CI 导航回归修复

Windows 工作流 40486171609 在印地语 WPF 设置导航检查中提前退出；旧调用只抛出通用失败消息，未保存子进程退出码。Mac 双架构与消息渠道检查已通过。

本地重复验证抓到独立的布局时序竞态：5 次原测试中有 1 次在切换模型页后找不到 `TextProviderName`。移除该处 40 ms 预等待后，旧查询也会失败。导航内容已经切换，但 WPF 尚未生成模板的可视子树。

修复与诊断：

- 查找实际控件前应用模板并完成布局，与现有设置页控件查找方式一致。保留原有 44 项导航、焦点、草稿和数据保护断言。
- 增加 `--layout-boundary` 回归模式，直接检查刚切换的模型页，取消该处预等待；CI 对全部 13 种语言使用此模式。
- 记录主题切换/截图阶段、内存及未处理异常；执行包装保存十进制/十六进制退出码、完整日志和原生异常事件。任何非零退出继续失败，不自动重试或放宽断言。

本地验证：13 种语言各 44 项断言通过，共 572 项；全部进程退出码为 0。另验证正常失败码 7 和原生异常式退出码 -1073741819 均保持失败，原样记录 `00000007`、`C0000005`。

本次不修改产品运行代码、版本号或翻译。最终远端 CI 全部通过后，才为对应精确提交创建 v0.11.2-dev.2 标签；main 0.11.1 和既有标签保持不变，不创建 Release。

## macOS Intel 设置关闭检查

后续工作流 40503119788 的 Intel UI 检查在 `failed feedback settings save does not dismiss a visible notice` 失败。此测试此前依赖 `SetInteraction` 延长同一提示寿命；0.11.2-dev.2 已按要求取消续命，截图和设置存盘超过 900 ms 后，自动消失会干扰设置观察。本地原检查也在截图时复现提示自然关闭（`ObjectDisposedException`）。

WPF 与 Avalonia 的该设置观察场景现在仅在测试内暂停提示的自动消失计时器，保留真实存盘、失败恢复和设置变更订阅，并刻意等待超过原寿命。失败存盘必须保持提示，成功禁用必须关闭同一提示；因此成功关闭不能靠自然超时蒙混通过。独立动画测试继续使用真实计时器验证 900 ms 和追加内容不续命，未改产品代码。

本地验证：Avalonia 伙伴主页 125 项、真实提示动画 10 项通过；WPF 伙伴主页测试编译通过。本机 WPF 执行被真实全屏状态抑制提示，未抵达本次场景，完整执行交由远端 Windows CI 验证。
