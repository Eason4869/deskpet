# 高清角色动作复验与整合计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. This supplements the existing companion-lifecycle ledger; do not restart completed tasks.

**Goal:** 将用户提供的五个修订角色包复验后纳入可重复构建的项目资源，并保留既有关系、节日纪念卡与用户数据。

**Architecture:** 以 `E:/data/HDskin` 的完整 ZIP 为只读来源，先核对文件与动作，再映射到项目的默认角色、扩展动作和节日资源。同步真实播放与打包元数据，不只替换图片；最终从新构建的角色包和应用安装包验证。

**Tech Stack:** Python/Pillow、C# WPF/Avalonia、现有角色包构建与校验脚本。

**Spec:** 用户于 2026-10-25 要求再次验证动作流畅性、肢体对齐并并入项目；原功能要求见 `implementation-plan.md`、`completeness-plan.md`、`holiday-keepsake-design.md`。

## Global Constraints

- 源目录只读，不覆盖用户提供的 ZIP、备份、预览及报告。附带报告是待复核的证据，不能代替本轮测试。
- 五角色稳定身份不变，日常与万圣节资源一并处理，保留非目标动作、视线、彩蛋及原有元数据。
- 不增加 MSI，不发布、不推送、不修改现有 tag，不操作用户实际安装和存档。
- 新应用目标仍为 `0.11.0-dev.1`；来源包名中的 `0.10.5-dev.3` 只表示来源版本，不当作此次应用版本。
- 审阅完成后才整合产品资源；与正在实施的 H1b 串行写产品文件。
- 实际播放、静态网格、像素指标、无头 UI 与真实桌面结果分别报告，不以其中之一代替全部验收。

## Review Focus

1. 打包脚本覆盖 fps，使最终包回到旧节奏：验证重建后的 manifest 与实际循环时长。
2. 默认动作与节日动作不同步，旧 WPF 路径沿用默认时长：验证两端的真实帧推进及跨循环边界。
3. 服饰版本更新破坏节日纪念卡领取：更新可信素材映射并验证新领取和旧记录读取、保存。
4. 仅复制导出包而未更新默认内嵌资源：核对默认角色、导入角色、打包产物三条路径。
5. 从静态像素差异误判动作正确：结合固定坐标逐帧、连续播放和身体部位对齐人工检查；眨眼帧单独核对。
