# 伙伴主页视觉修订

用户在 2026-10-24 的实际截图审核中要求美化主页、增加图形表达。本修订纳入已授权的 S2，保留原有功能与数据规则。下面的视觉取舍由实现方提出，交付实际截图供用户继续审核，不表示用户已逐项确认。

## 设计方向

采用「伙伴档案与相伴纪念册」：头像和关系是主角，成长记录是连续时间轴，纪念卡直接展示图像。沿用应用蓝色、圆角、字体、浅深主题。单纯把现有文字套入等大的卡片仍然缺少层次；大面积角色海报又会挤压可操作内容，因此选择紧凑档案与关系主视觉结合。

## 页面结构

内容居中，最大宽度约 1080，常规边距 28，窄窗口边距 16。页面标题清晰但不抢伙伴主体。宽屏顶区左侧约 36% 为伙伴档案，右侧为关系信息；可用宽度不足 760 时顺序改为单列，不出现横向滚动。

1. **伙伴档案**：原色真实头像约 88–104，名字放头像右侧，简介下置且长文可折叠。使用浅蓝柔和底色与小范围圆形背景衬托头像，深色使用现有主题色阶。无虚构心情标签、头衔或经历。
2. **我们的关系**：阶段标签、分数与下一阶段说明组成紧凑主区。圆形进度图中心使用简洁心形图标，旁边显示 156 / 240、还差 84 点；同一处可访问文本表达完整含义。进度为累计分数/下一阶段阈值，最高阶段显示 1000 / 1000。下方六个阶段节点表达先后顺序，已达成实色、当前描边、未来空心/锁定，并保留文字，不能只靠颜色。节点等间距是阶段序列，不伪装成线性积分轴；窄屏分两行或使用垂直序列。
3. **相伴积累**：今日获得、有效相处天数、认识天数采用三个紧凑图标与数值单元，不为每项嵌套厚卡片。今日 6 / 20 只表达收益，不使用任务勾选清单。状态与保存/读取警告贴近关系主区，不能埋在页底。
4. **相伴历程**：细连接线、阶段节点、标题、达成日期组成真实时间轴；只显示已保存里程碑，不推算历史或虚构未来日期。空状态提供简洁欢迎和成长说明。
5. **纪念卡**：宽屏并排、窄屏单列，默认就能看到真实卡片缩略图，包含头像、姓名、阶段、日期。点击展开等比预览，旁边保留“保存纪念卡”动作。缩略图、展开图和导出使用同一份捕获数据及 PNG，不在预览时落盘。卡片旁或展开区继续显示该已解锁阶段的真实欢迎语，不能因改为图像而丢失原先回看文案的能力。无需另开窗口。卡面随捕获时的浅深主题渲染；切换主题重建 PNG 并保留展开与滚动，缩略图、展开图和导出仍共用同一捕获。
6. **成长规则与关系设置**：页底分组折叠区，有统一图标、标题、展开指示与分隔线。规则用见面、互动、对话、工作四个图标行说明数值及上限。设置采用现有开关样式，标题与解释分层，明确这些开关对所有伙伴生效。保留键盘、自动化名称和保存中禁用行为。

## 视觉与工程约束

- 使用现有 ThemeManager / Ui / AgentUi 与 Avalonia 对应资源，主体文本用主题 Ink，次级文本用 Muted，蓝色用现有强调色。卡片圆角 16–18，内部图标底圆角 10–12，按钮沿用现有样式。字号层级为页面标题 26、伙伴名 24、区域标题 18、正文 14、次级 12–13；字体继续使用本应用字体，不引入外部字体或框架。
- 图形使用原生矢量路径/几何图元和现有图标，避免依赖 emoji 字形。圆形进度不能带来周期动画、发光特效或持续 CPU 开销。对有操作的区域提供悬停和键盘焦点反馈，静态图形不进入 Tab 顺序。
- 深色主题逐项核对图标、轨道、锁定态、正文、按钮，不把浅色截图整体染黑。保持适当对比度与文字换行，长名字不挤掉分数；可截断名字但提供完整辅助文本。
- 用户第二轮截图审核明确要求深色模式下纪念卡等背景也深色化：两端卡片渲染器按捕获时主题输出真实深色 PNG，缩略图、展开预览与保存图片一致；不能只将外框染黑而内部仍是白色图片。主题切换使卡片捕获缓存失效，更新卡面文字、背景与边框，同时保留展开和滚动。保存对话框打开期间继续使用该次捕获数据和主题的同一 PNG，避免异步串用。浅色模式保留浅色卡面。深色及主题切换后的实际截图和导出图片必须验证。
- 用户进一步明确卡牌深色必须与页面背景区分：卡面采用比页面 Surface 更亮一阶的蓝灰色（例如卡面 #2B3545，依据实际主题校准）与柔和边界，保持清楚的卡片轮廓。验证实际 PNG 卡面像素与页面背景存在区别及文字对比度，不能只验证“不是白色”。这一层次也体现在导出图片内。
- 共享投影唯一计算阶段、阈值、日期、状态，界面不复制成长业务逻辑。拆分小型展示控件，避免继续扩大主窗口类。
- 后台增长保留展开状态、合理滚动位置与焦点；快速换伙伴清除旧预览，迟到结果不能显示到新伙伴。错误状态保留原文件，提供真实可恢复的重试或明确重启说明和打开数据目录入口。
- 全部新可见文案进入 13 语言资源，字面量 camelCase 键；当前中文截图中通用英文欢迎语由最终多语言门禁修复，视觉审核时明确标注。

## 实施与验收

S2 在 M5c1 审阅通过后优先执行，随后恢复 M5c2、S1、S3、M6。S2 原先承诺的状态解释、预览、恢复与刷新保持全部继续执行。截图至少覆盖两端浅/深色、宽/窄、零分、156 分、1000 分、暂停/日上限、读取错误、展开规则/设置/预览。真实产品截图更新现有审核图库，旧截图保留用于对照。检查 390/520 窄宽及 1100/1320 宽屏、不重叠、不裁切、不出现多余横向滚动。自动化验证真实绑定数据、保存前不落盘、切换不串图及刷新状态；人工视觉检查不能被控件存在断言代替。Windows 无头渲染与 macOS 实机分别记录。
