# 伙伴主页、好感度与数据管理：合并开发计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 当前文件是计划，不代表产品代码、测试、安装包或发布已经完成。

**Goal:** 让日常陪伴产生可见、可靠的长期关系成长，同时提供保留个人资料的缓存清理与边界明确的数据管理。

**Architecture:** 好感度、伙伴身份、成长事件、持久化和维护规则放入共享逻辑，WPF 与 Avalonia 使用相同结果。页面、反馈和图片导出分别使用两端现有 UI 与主题系统，以小型新文件接入现有窗口。

**Tech Stack:** 现有 C#、Windows WPF、Avalonia、项目已有原子写入和内嵌语言资源；保留当前运行时兼容要求。

**Spec:** 本文第 2–10 节是两组用户要求的合并规格；前置维护设计见 `maintenance-design.md`。发生冲突时，以本文的数据保留边界及用户后续决定为准。

**状态：** 已合并需求，用户已授权以 v0.10.5-dev.3 为基线实施，目标 0.11.0-dev.1。用户给出的范围为主；以下阶段阈值、单次收益和未指定交互属于可调整的开发默认值，不表示用户已经逐项选择。

## 2. 首版功能与后续扩展

首版包含：

1. 可点击、保持原色的伙伴菜单信息区。
2. 主窗口内的伙伴主页及现有导航历史接入。
3. 每个伙伴独立的好感度、关系阶段、相处天数和认识时长。
4. 见面、主动互动、完整对话和成功工作任务的成长。
5. 通用阶段欢迎语、阶段里程碑、纪念卡及图片保存。
6. 独立本地持久化、首次启用初始化、升级迁移和现有 13 种语言支持。
7. 缓存清理弹窗、通用设置中的数据管理，以及取消卸载时保持桌宠运行。

后续分批接入装扮收藏、角色故事、记忆管理和当前心情。既有衣柜和已安装角色继续保留；本轮不扩展这些系统，也不为未实现功能放置无法使用的主页入口。

好感度表达长期关系；未来心情单独建模，不能通过短期心情变化覆盖长期分数。

## 3. 入口、导航与伙伴主页

### 3.1 伙伴菜单信息区

- 修正 WPF 菜单顶部 `IsEnabled=false` 导致的灰显与不可点击。
- 保留当前伙伴头像和名字，副标题改为“查看伙伴主页”，右侧显示箭头。
- 正常状态保持头像原色；悬停、键盘聚焦和按下状态均有明确反馈。
- 可通过 Tab、方向键及确认键访问，具备可读的辅助功能名称。
- 点击后关闭菜单，在现有主窗口显示伙伴主页；接入返回、前进历史，不为主页创建额外弹窗。
- Avalonia 提供等效入口；主页切换后不丢失聊天草稿及当前会话状态。

### 3.2 页面四个区域

| 区域 | 首版内容 |
| --- | --- |
| 伙伴档案 | 原色头像、名字、角色简介；长介绍可折叠 |
| 我们的关系 | 当前阶段、累计分数与下一阶段门槛、今日增长、相处天数、认识时长 |
| 相处历程 | 首次见面、阶段达成和关系里程碑；空状态使用简短欢迎内容 |
| 关系纪念 | 已解锁阶段欢迎语与纪念卡，可再次查看和保存图片 |

示例：`熟悉 · 156 / 240`、`我们已经认识 18 天了`、`再积累 84 点好感度，关系将进入「亲近」`。这些数值来自实际记录；没有数据时不填入演示天数。

- 窄窗口单列；宽窗口可让伙伴档案与关系卡并排，其余区域顺序保留。
- 沿用现有浅色与深色主题、字体、按钮及滚动样式。
- 页面底部提供“成长规则”和“关系设置”，可使用内联展开区，避免为简单说明增加窗口。
- 当前伙伴切换后刷新档案与关系数据；返回主页时显示当前伙伴，不把旧头像与新分数混在一起。

## 4. 好感度、阶段与成长默认值

### 4.1 阶段

分数为 `0–1000` 的累计整数，阶段始终由分数计算。默认阈值：

| 阶段 ID | 中文默认名 | 进入所需累计分数 | 下一阶段累计门槛 |
| --- | --- | ---: | ---: |
| first_meeting | 初识 | 0 | 80 |
| familiar | 熟悉 | 80 | 240 |
| close | 亲近 | 240 | 480 |
| trusted | 信赖 | 480 | 760 |
| heartfelt | 知心 | 760 | 1000 |
| best_friend | 挚友 | 1000 | — |

达到 1000 后停止加分，继续记录有效相处日、认识时长和里程碑。离线、未签到或长期不使用均不扣分，不设置连续签到惩罚。

阈值集中配置并具有规则版本，阶段显示名进入语言资源。后续改动阈值时，保留已获得的纪念记录，并明确执行迁移。

### 4.2 每日成长

默认每个伙伴每日总收益最多 **20 点**，各类限额是收益限制，不是每日必做清单。

| 来源 | 单次收益 | 单类每日收益上限 | 条件 |
| --- | ---: | ---: | --- |
| 当天首次见面 | +2 | 2 | 当天首次实际展示伙伴，或主动打开其主页；纯后台启动不算 |
| 主动互动 | +1 | 6 | 用户发起且角色实际执行；收益间隔至少 20 秒 |
| 有效对话 | +2 | 8 | 用户输入获得成功的完整回复；文字、语音使用同一规则 |
| 成功工作任务 | +4 | 8 | 用户发起的顶层任务成功完成；以根任务为单位 |

- 各类上限合计 24，但总收益始终截断至 20；结算顺序以真实事件完成顺序为准。
- 单个事件可以只获得距离总上限剩余的点数，例如仅剩 1 点时工作任务获得 1 点。
- 最快约 50 个满额活跃日到达挚友；仅见面和主动互动也能持续成长。
- 达上限后功能照常使用，不弹出催促完成其他项目的提醒。
- 主页显示“今日已积累 … / 20”，以及真实剩余进度，不展示强制每日任务清单。

### 4.3 完成判定、去重与伙伴归属

- 对话以稳定的逻辑用户轮次 ID 去重，不能用每次重新生成的回复 ID 作为唯一依据。
- 失败、取消、工具消息、内部子任务不计分。一次失败后的最终成功可结算一次；同一成功轮次的重试、重新生成与重复完成通知不再结算。
- 工作任务以稳定根任务 ID 去重；工作完成不再同时作为普通对话获得另一份收益。
- 工作任务创建时保存伙伴稳定身份；切换角色、重启恢复、内部子任务和重试不能改变其归属。
- 用户轮次也在开始时绑定伙伴，避免回复期间切换角色导致误归属。
- 语音识别成功本身不计分；由识别输入最终获得完整回复后结算。Live 仅在双方完整轮次可明确识别时使用同一去重规则，音频片段不计为多轮。
- 系统自动问候、后台启动、AI 自发输出与自动播放动作不产生互动收益。

## 5. 反馈、内容解锁与关系设置

### 5.1 日常反馈

- 普通收益短暂显示“好感度 +N”，近时间发生的收益合并提示。
- 反馈不抢焦点、不改变页面、不打断正在输入的内容。
- 免打扰或关闭反馈时仅更新主页；不在退出免打扰后集中补放提示。
- 保存成功后才展示已获得的分数和解锁结果；保存失败显示可重试状态，不能先显示成功再回滚。

### 5.2 阶段与纪念卡

- 首次跨越阶段后显示一次小型成长卡，执行角色已有的适合动作，并记录达成时间。
- 缺少专属动作时使用已有通用动作；忙碌或免打扰时不强行打断角色状态。
- 解锁结果先持久化；自动提示的领取也需要幂等处理。关闭提示后，仍可在主页查看纪念卡。
- 纪念卡包含头像、名字、阶段和实际达成日期，支持通过保存对话框导出 PNG。
- 导出成功以真实文件写入为准；处理取消、重名、无写权限、长名称和多语言字体。
- 用户导出的纪念卡属于用户图片，缓存清理不得删除。

### 5.3 角色内容和 AI 语气

- 欢迎语、互动回应优先读取角色包中与阶段、语言匹配的内容；缺失时使用首版通用文案。
- 内容包扩展字段可选，旧角色包继续可用。文案长度和动作标识必须校验，未知字段不触发任意文件或命令访问。
- 阶段解锁欢迎语和纪念卡属于首版内容；后续装扮、故事和记忆解锁使用独立扩展接口。
- AI 可接收简短、真实的阶段说明；用户人格和明确偏好继续优先生效。
- 不凭空编造昵称、生日、共同经历或个人资料；这些只能引用已保存的真实资料。
- 通用内容先覆盖全部阶段和现有语言，官方角色专属文案可后续逐步补充。

### 5.4 关系设置默认项

- 记录关系成长：默认开启；关闭后保留已有记录，暂停新增关系记录与收益。
- 显示成长反馈：默认开启；关闭不影响成长结算与主页查看。
- 让 AI 了解关系阶段：默认开启，只注入简短阶段信息；关闭后停止注入。
- 首版不增加含义模糊的“一键清理全部关系”按钮。未来如增加关系重置，必须是独立操作、明确范围并单独确认。

## 6. 身份、时间、存储与迁移

### 6.1 伙伴与装扮

- 关系键使用伙伴稳定身份，不能使用显示名称、头像路径、安装目录或装扮文件名。
- 已验证官方伙伴使用稳定官方角色 ID；自定义包使用持久导入身份，同名的独立导入角色不会共用关系。
- 同一伙伴换装、更新内容包、改名或修改头像沿用原关系；角色隐藏后保留数据，恢复后可继续。
- 旧格式角色在首次启用时建立持久映射；映射迁移不能因重新扫描目录而生成新身份。
- 自定义内容包不能仅通过声明官方 ID 占用官方伙伴关系。

### 6.2 建议记录

| 数据 | 用途 |
| --- | --- |
| SchemaVersion、RulesVersion、伙伴稳定 ID | 兼容、迁移与隔离 |
| Score | 累计分数；当前阶段从该分数计算 |
| FirstMetUtc、首次有效本地日期、LastSeenUtc | 认识时长与重逢问候 |
| 有效相处日期集合或等效可靠索引 | 累计相处天数，区别于认识时长 |
| 日预算、分类计数、上次互动 UTC 时间 | 每日上限与 20 秒收益间隔 |
| 事件去重凭据、根任务及其伙伴归属 | 重试、重启和重复通知幂等 |
| 阶段达成 UTC、本地日期及解锁记录 | 历程与纪念卡 |
| 成长提示处理状态、关系设置 | 提示去重和用户偏好 |

### 6.3 时间规则

- 按有效相处的本地自然日累计相处天数，不按应用启动次数累计。
- 认识时长按首次见面日期计算，首次当天记为第 1 天；日期异常时不显示负数。
- 同时保存 UTC 与本地日期/偏移信息。正常本地跨午夜可以获得新一天的额度。
- 重启和重复打开主页不能重复领取当日见面收益。
- UTC 时间回拨时不新增收益，保留已有数据并等待时间恢复；不能重开已结算的旧日期。
- 时区变化本身不重置当日额度：携带当前预算到新的日期锚点，后续正常跨日再刷新，且已结算日期不能再次领取。
- 用可注入时钟验证午夜、夏令时、时间回拨和跨时区；不依赖测试机器实际修改系统时间。

### 6.4 可靠存储与升级

- 关系数据独立保存，与设置、历史、图片和缓存分离；存储根由现有数据目录决定。
- 同一次成长中的分数、日计数、去重凭据和解锁记录作为一次事务提交，采用项目已有的可靠写入方式。
- 写入成功后更新界面；失败时保留上一个成功状态，重试复用同一事件 ID。
- 多入口共享同一写入协调器；如果存在多个进程写同一数据目录，必须有独占协调或冲突保护。
- 校验格式、大小、字段范围和路径归属；损坏或更高版本数据不得被静默覆盖成空白。
- 老用户从系统启用之日开始记录，不从已有聊天推算历史好感度。
- 后续 schema 变更需要版本化迁移、备份和失败保护；旧客户端不能错误覆写新 schema。
- 重逢问候根据真实 LastSeenUtc 选择，离线时间不扣分，也不自动增加相处天数。

## 7. 缓存清理

### 7.1 入口与弹窗

- WPF“关于”页底部在红色“卸载”左侧增加灰色次要按钮“清理缓存”，两按钮保持视觉区别。
- Avalonia 在已有关于或数据管理入口提供等效能力，不引入其他平台不存在的 Windows 卸载动作。
- 异步扫描后显示真实估算，例如“可清理约 128 MB”，按类型显示容量与项目。
- 分类包括过期更新包、可确认已遗留的临时下载文件、实际存在且可重建的磁盘缩略图。
- 当前没有磁盘缩略图缓存时，不虚构可释放容量；无项目的分类可不显示。
- 常驻说明：设置、API 密钥、聊天记录、已安装角色、用户图片和关系成长数据均保留；使用中或下载中的文件跳过。
- 零可清理空间时禁用执行；清理后显示实际释放空间、跳过项和失败项，允许重新扫描。
- 取消、Esc 和关闭只关闭弹窗，桌宠继续运行；避免同时启动多个清理任务。

### 7.2 安全范围

- 使用已确认的目录与文件类型白名单，不根据 cache、temporary 或 .tmp 名称遍历并删除整个数据根。
- `data/updates/<ID>` 中仅清理已过期且未被引用的文件；活动下载、待安装更新和回滚必需文件保留。
- 角色下载 `.stage-*`、`.transfer-*` 仅在确认已遗留时进入候选；已安装角色目录始终保留。
- 生成图的 temporary-* 目录可能含有用户图片，不因为“临时”命名进入清理范围。
- 执行前重新检查归属、过期状态和活动资源保护，覆盖扫描后才开始下载的竞态。
- 跳过占用、权限不足、无法确认安全的文件，以及符号链接、junction 和其他重解析点。
- 所有删除测试使用隔离目录，绝不对用户真实数据目录执行破坏性验收。

## 8. 通用 → 数据管理

沿用现有聊天记录保存设置，将 WPF 对应子页整合为“数据管理”；Avalonia 提供对应操作。每项有明确描述和独立确认，不使用笼统的“清理数据”按钮。

### 8.1 清空聊天记录

- 范围：所有伙伴及项目对话的聊天记录和对应模型会话上下文。
- 明确说明不可撤销；清空内存与落盘记录，防止重启、切换伙伴或另一个打开会话把旧历史重新写回。
- 保留模型配置、密钥、伙伴、人设、图片、关系记录、项目定义、工作目录和源文件。
- 已获得的好感度与纪念卡不撤销；关系去重记录继续保留，清空历史不能成为重复领分途径。
- 发送、录音、Live、队列或相关后台任务运行时暂不执行；确认后、真正执行前再次检查并建立维护占用保护。
- 不能删除仍在运行任务的进程所有权记录或伪报全部成功；部分失败必须具体报告。

### 8.2 恢复默认设置

- 本计划默认范围：外观、桌宠行为、通用偏好和快捷键的默认值。
- 保留模型配置及密钥、伙伴与人设、图片、聊天、关系成长和关系设置、工作区配置及更新通道。
- 不清空里程碑、不重新触发首次配置引导，不改变 AI 关系注入等已保存的独立关系偏好。
- 确认框分别说明恢复和保留的项目；取消、Esc 和关闭无副作用。
- 通过已有设置保存/应用路径执行，成功后刷新当前界面；失败不能显示成功。

## 9. 卸载确认

- 点击红色“卸载”先确认，说明将移除程序文件、保留用户数据。
- 取消、Esc 或关闭确认框不启动卸载，不退出桌宠。
- 用户明确确认后，再检查任务忙碌、保存状态和注册卸载器路径；启动失败保持桌宠运行。
- 交接不能让桌宠在用户尚可取消卸载时就提前退出。优先使用一次应用确认和已注册卸载器支持的无二次确认交接；具体方式必须核对官方参数与真实安装流程。
- 便携版缺少注册卸载器时明确说明，不自行删除应用目录或用户资料。
- 真实卸载仅在专用测试安装中验收，并检查取消、执行失败、实际卸载和用户数据保留。

## 11. 全局实施约束

- 关系规则与维护规则共用数据边界，WPF 和 Avalonia 不各自计算分数或定义删除范围。
- 计分范围 `0–1000`，每伙伴日上限 `20`，互动收益间隔 `20 秒`。
- 首版不追溯历史好感度，不因离线扣分。
- 活动下载与未完成任务具有明确的资源归属；所有数据维护在执行前重查占用。
- 每个里程碑的保存、去重和展示有可验证顺序，写入失败不显示成功。
- 不修改已有发布 tag；不把本地测试、真实桌面验收、安装包验证和远端 CI 混为一个“已通过”。
- 默认使用独立工作区。已创建的 `E:/workspace/deskpet/companion-relationship` 分支为 `codex/companion-relationship`，已在用户指定的固定 v0.10.5-dev.3 基线上实施；不得把其他 dev 后续改动默认为已包含。
