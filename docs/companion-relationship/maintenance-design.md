# 0.10.6-dev.1：缓存清理、数据管理和卸载确认

## 用户要求

- “关于”页底部在红色“卸载”左侧增加灰色次要按钮“清理缓存”。
- 小弹窗展示实际扫描所得的“可清理约 …”，并按类型列出可清理项目。
- 缓存清理保留设置、API 密钥、聊天记录、已安装角色和用户图片；正在使用或下载的文件跳过。
- “通用 → 数据管理”提供“清空聊天记录”“恢复默认设置”等明确操作，各自确认。
- 关闭或取消卸载确认时，桌宠继续运行。

## 当前实现和约束

- 远端 dev 与 v0.10.5-dev.3 均指向 fde04835ffce544c334205d881a232c579ded4df；新开发基于此后的最新 dev，版本为 0.10.6-dev.1。
- Windows WPF 的关于页为 src/AboutPanel.cs，通用设置为 src/QuietPanel.cs，目前第三个子页是历史记录保存设置。
- AboutPanel.Uninstall 启动卸载程序后立即 pet.Close()，因此关闭卸载向导也会丢失正在运行的桌宠。
- 更新缓存位于 data/updates/<随机 ID>；UpdateCoordinator 会持有正在下载、待安装或正在应用的更新。
- 角色下载存在 .stage-* 和 .transfer-* 暂存目录；不得把整个角色存储目录视为缓存。
- 图片库的 temporary-* 目录也可能包含用户图片，不可因名称含 temporary 就删除。
- 当前 WPF 图片缩略图主要驻留内存；弹窗不能把不存在的磁盘缩略图缓存计入可释放空间。
- 项目同时有 Avalonia 桌面端；复用清理核心，并在现有关于/存储入口提供对应能力，不虚构其他平台的 Windows 卸载操作。

## 方案选择

采用“共享维护服务 + 现有 UI 接入”：将扫描、保护、执行和结果统计集中处理，WPF 和 Avalonia 调用相同规则。

不采用按扩展名全盘扫描或删除整个缓存/临时目录：实际临时目录中可能含有用户图片、待安装更新和正在发布的角色资源，无法满足用户明确的保留要求。

不在两个 UI 内分别编写删除规则：重复实现容易造成保护边界不一致。具体类名和内部接口由实现时确定。

## 缓存清理交互

1. “清理缓存”与“卸载”位于同一页脚操作区，左灰右红，窄窗口下仍可见。
2. 打开小弹窗后异步扫描；扫描阶段显示状态，尚未得到结果时禁用清理按钮。
3. 展示总量和分类：过期更新包、可确认已遗留的下载暂存文件、实际存在且可重建的缩略图缓存。没有文件的分类显示零或不显示，不伪造空间。
4. 保留说明始终可见：设置、API 密钥、聊天记录、已安装角色和用户图片不会被清理；使用中或下载中的文件跳过。
5. 点击“清理”后重新验证文件资格。显示实际释放字节数和跳过数量；失败项保留并提示，可重新扫描，不影响桌宠继续运行。
6. 取消、Esc 和窗口关闭只关闭弹窗；零可清理空间时禁用清理按钮。

### 删除边界

- 仅允许应用拥有的明确目录和文件类型；不能根据 .tmp、cache、temporary 等名称在数据根目录递归删除。
- 已过期且未被更新器引用的更新文件可清理；待安装更新、更新回滚所需文件、活动下载及活动解压目录必须保护。
- 为更新与下载流程增加活动资源保护，使扫描和执行之间新开始的操作也不会被误删。占用文件、权限不足文件和近期无法判定是否活跃的暂存文件跳过。
- 验证规范化绝对路径和目录归属；不跟随符号链接、junction 或其他重解析点；执行前重新验证。
- 已安装角色内容、原图、生成图、参考图、聊天附件、模型配置及加密密钥不进入候选集。
- 清理在后台执行，保持 UI 响应，避免重复启动同一清理操作。

## 通用 → 数据管理

沿用现有第三个子页，将标题改为“数据管理”，保留聊天记录保存开关，并增加两个独立区域。

### 清空聊天记录

- 确认文案明确：永久清空所有角色及项目对话的聊天记录，无法撤销；保留设置、密钥、角色、用户图片、项目目录和源文件。
- 操作覆盖内存中的会话记录与落盘历史，包括对应的模型上下文，避免清空后从内存或另一个打开的会话重新写回旧记录。
- 发送、录音、Live、队列或后台任务占用相关会话时，暂不执行并提示先结束任务；确认后开始执行时再次检查。
- 不删除项目源文件、用户图片、工作区配置或后台任务的进程所有权记录；失败时明确报告，不能声称已全部清空。

### 恢复默认设置（实现提案）

- 恢复外观、桌宠行为、通用偏好及快捷键的默认值。
- 保留模型配置及 API 密钥、角色及人设、用户图片、聊天记录、工作区配置和更新通道；不重新触发首次配置引导。
- 确认框逐项说明重置与保留范围；关闭或取消没有副作用。
- 使用现有设置保存与应用路径，刷新当前界面；保存失败不能显示成功。

## 卸载确认

- 点击红色“卸载”先显示明确的应用内确认，说明卸载程序文件及保留用户数据的范围。
- 取消、Esc 或关闭确认框不得启动卸载，也不得关闭桌宠。
- 只有用户明确确认后，才重新检查忙碌状态、保存状态和已注册卸载路径，并进入卸载。
- 不保留“先关桌宠，再让用户在另一层确认中取消”的路径。优先让应用内确认成为唯一确认，再使用已注册卸载器支持的无二次确认方式完成交接；具体参数必须核对卸载器官方文档并用隔离安装测试验证。
- 启动失败时保持桌宠运行并显示错误。便携版缺少注册卸载器时保留明确说明，不删除用户目录。

## 实现和验收

- 使用独立开发工作区，避免修改其他会话正在验证的 dev.3 工作区；不更改已建立标签。
- 先写有实际文件隔离夹具的回归测试，再实现：保护文件不变、活动下载/待安装更新跳过、链接越界跳过、扫描后状态改变跳过、占用/拒绝访问处理、实际空间统计。
- 数据操作测试覆盖所有角色和项目会话、清空后重启不恢复旧记录、忙碌状态拒绝、恢复默认值保留密钥/模型配置、失败不报成功。
- 卸载 UI 测试覆盖取消、Esc、关闭不退出；隔离安装测试覆盖确认后的真实卸载流程，不能卸载用户当前安装。
- 两端 UI 验证入口、独立确认和布局；Windows 关于页至少检查常规和最小窗口尺寸、浅色和深色主题。
- 接入现有多语言资源与完整性检查；更新中英文变更记录和必要使用说明，版本更新至 0.10.6-dev.1。
- 执行针对性测试、相关回归与构建，完成代码审查后交付可审阅改动；远端 CI/发布状态与本地验证分别报告。
