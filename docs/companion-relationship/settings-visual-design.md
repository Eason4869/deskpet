# 设置与数据管理视觉修订

用户在截图审核中再次明确要求美化 Avalonia「设置 → 数据管理」。其多行横向 Tab、堆叠灰按钮、未分组的应用工具和长路径来自实际布局；`App.Initialize` 与截图 `TestApp.Initialize` 都安装 FluentTheme 和 DesktopAppearance，不能归因于截图未加载主题。此修订作为 F2，接在当前 S2 之后优先执行。以下是实现方的具体设计取舍，实际截图仍交用户审核。

## 范围与保留要求

优化现有 Avalonia 设置窗口导航及数据管理，不把整个设置系统迁入主窗口，也不重写模型编辑器、工作设置等业务。保持全部现有类别可达、SelectSection 路由兼容、模型子页选择与未保存输入不丢失。WPF 数据管理的操作行与确认弹窗同步采用相同层次；WPF 既有侧边导航不重做。历史清理、偏好白名单、维护租约、附件保留、失败结果均继续使用已审阅服务，不更改删除范围。

## 视觉结构

1. **设置导航**：Avalonia 外层类别从多行横向 Tab 改为紧凑侧边导航，宽约 170–190，有适量矢量图标、选中底色和键盘聚焦反馈。内容区显示明确页标题与简短说明，导航过高时独立滚动。现有最窄 570 窗口仍可操作；侧栏可略收窄，内容操作行改为上下布局，不能通过提高最小宽度掩盖溢出。长语言标签允许合理换行但保持整行命中区。内部仅两个模型页签可以保留。复用现有页面实例，切换类别不能重建并清空提供商输入；恢复偏好仍只刷新原有允许刷新区域。
2. **聊天记录**：聊天/锁图标、标题、保存开关与说明，和“清空全部聊天记录”危险操作组成清晰区域。说明本机保存及其范围，清空按钮使用低强调红色文字/边框；点击只打开确认，不直接执行。
3. **默认偏好**：调节图标、恢复默认偏好的标题与简短保留说明，右侧次要按钮；窄屏按钮移至正文下方。不要把恢复偏好呈现成清除所有数据。
4. **保留附件**：文件夹图标、入口及保留意义独立成行，空目录、打开失败及 Busy/Partial 等结果在相关区域清楚显示。保留原控件名与功能。
5. **本地存储与应用工具**：完整路径默认折叠，概要显示“本地数据目录”和打开按钮；展开后完整路径可选择/复制并换行，不使用技术测试路径作为页面主体。网络加速、角色下载进度、配置向导、关于等原有入口保留在明确命名的应用工具折叠区，避免与清空、重置混排。不得悄悄删除入口。
6. **独立确认弹窗**：两端保持现有所有权、取消/Esc/X、执行中防关闭、结果与关闭流程。用简洁警示图标、标题、完整作用/保留范围、紧凑留白、清晰的取消与危险/次要确认按钮表达后果。长文本仍可滚动；不得把保护范围为美观删短到失真。危险动作不设意外默认 Enter 执行，不改变服务调用或引入新的自动执行。
7. **缓存清理弹窗的一致性**：同批实际截图也显示纯文本堆叠与大块空白，因此一并进行有限展示修订。可清理空间作为主要数值，下方用原生图标分类行展示真实扫描的过期更新包、遗留下载等现有项目，保护/失败计数、完整保留说明与执行结果清楚分层。只消费现有 CacheScan/CachePresentation，不新增清理类别、文件搜索或删除策略，不绘制虚构容量占比；零空间、扫描失败和清理后结果均真实表示。保留现有清理/重扫/取消、异步窗口关闭和控件自动化契约。两端浅深与零/非零/结果截图随 F2 验证。

继续使用应用既有蓝色、Ink/Muted、浅深主题、字体和 12–18 圆角层次。图标使用现有图标或原生矢量；选中、悬停、键盘焦点不能只依赖全局被关闭的焦点装饰。不要全局修改所有 Button/Tab 样式造成其他窗口回归。数据管理不是统计仪表盘，不新增无意义进度图或虚构存储统计。

## 实施与验证

- 先覆盖真正行为风险：所有分类/子路由可达，切换保留编辑中数据，偏好恢复后控件更新且其他输入保留；搜索/路由不会触发危险操作。
- 现有数据维护和确认测试继续通过，不重复重测全部共享删除实现。新增断言仅验证有意义的导航、状态和布局边界。
- 两端截图至少包含中文、英语，浅/深色，窄/宽，完整数据页与两种确认、空附件/部分失败状态。截图来自真实界面；Avalonia Windows 无头不冒充 macOS 实机。
- 核查可读字号、足够点击区域、无多行拥挤顶级导航、按钮不裁切、完整保留范围可查看、路径不撑宽；手工视觉检查与自动断言分别记录。
- 新文字用字面量 camelCase 资源键，13 语言一致，历史基线不漂移。报告测试、实际截图与限制，更新审核图库。
