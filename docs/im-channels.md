# 消息渠道（开发分支）

本功能基于 main 0.11.1 开发，尚未发布。入口为设置中的“消息渠道”。

## 工作条件

用户自行创建/绑定机器人，桌宠主动连接平台官方服务。无需公网 IP、端口映射、内网穿透、云函数或开发者提供的服务器，也无需安装 Node、Python、OpenClaw 或 AstrBot。

电脑必须开机、联网且桌宠正在运行。退出、睡眠或断网期间不能处理消息；不承诺所有离线消息都能补收。模型使用现有“模型配置”，用量由用户自己的模型服务计费。模型设置在连接时冻结，更换后重新连接生效。

首版提供文字对话。远程消息不开放 Agent、文件、终端、GitHub 写入、图像/语音生成或桌面操作。上下文与桌面私聊隔离，只在内存中保留，暂停、编辑配置、重新连接、维护或退出都会清除该连接的上下文。

## 配置步骤

1. 打开设置 → 消息渠道 → 添加连接。
2. 选择平台，填写名称和平台凭据。新连接绑定当前伙伴与当前人格；切换桌面伙伴不会改变已保存的绑定。
3. 保存并连接。发送者允许列表为空时，任何人都不能调用模型。
4. 从机器人发送一条消息，回到设置查看“最近发送者 / 群”。将自己的发送者 ID 加入允许列表，每行一个。群聊还要加入群 ID，且通过 @机器人触发。
5. 再次保存。允许的用户发送文字后，即可开始对话。

不要把 AppSecret、登录令牌或二维码粘贴到公开聊天或问题反馈中。诊断只记录状态，不包含平台原始消息、令牌或消息正文。

## 平台准备

| 平台 | 机器人类型 | 填写内容 | 收消息方式 |
| --- | --- | --- | --- |
| qq | QQ 开放平台官方机器人 | AppID、AppSecret | WebSocket |
| weixin | 微信 ClawBot 绑定 | 在桌宠中点击“微信扫码登录” | HTTPS 长轮询 |
| feishu | 飞书企业自建应用机器人 | App ID、App Secret | 官方长连接 |
| dingtalk | 钉钉内部应用 Stream 机器人 | Client ID、Client Secret | Stream |
| wecom | 企业微信智能机器人 API 模式 | Bot ID、Secret | WebSocket |

### QQ

在 [QQ 开放平台](https://q.qq.com/) 创建机器人并获取 AppID/AppSecret。选择平台支持的 WebSocket 接收方式。先验证自己的私聊；群能力取决于机器人账号实际开放范围。

这是 QQ 官方机器人接入，不能将普通个人 QQ 账号当作机器人账号登录。依据：[当前腾讯官方实现](https://github.com/tencent-connect/openclaw-qqbot/blob/main/README.zh.md)、[协议 SDK](https://github.com/tencent-connect/qqbot-nodejs/blob/main/README.zh-CN.md)。

### 微信

选择 weixin，填写连接名称后点击“微信扫码登录”。二维码在本地生成，用手机微信扫描并确认；成功后令牌加密保存在本机。取消、二维码过期或账号失效时重新扫码。

仅支持该入口授权的一对一文字对话，不承诺微信群、读取其他联系人或历史聊天。账号是否拥有相关入口及服务器是否接受兼容客户端，需要真实账号验证。当前不处理短信/验证码式额外验证；遇到需额外验证时取消并在微信中完成平台要求后重试。

依据：[腾讯插件及协议](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol.md)。网络字段采用该协议版本；客户端以 DeskPet 标识自身。

### 飞书

在 [飞书开放平台](https://open.feishu.cn/app/) 创建企业自建应用，启用机器人，申请必要的收消息、以机器人身份回复及机器人信息读取权限，订阅 `im.message.receive_v1`。选择长连接并发布应用，确保测试用户处于可见范围。群聊使用真实 @机器人触发。

无需配置事件回调 URL。长连接消息接收与交互卡片回调不是同一能力；首版不提供远程审批卡片。依据：[官方 SDK](https://github.com/larksuite/node-sdk/blob/main/README.zh.md)。

### 钉钉

创建企业内部应用，添加机器人能力，选择 Stream 模式并发布，获取 Client ID（AppKey）和 Client Secret。不要选择只向群发送通知的普通自定义 Webhook 机器人。

回复使用平台消息提供的短期回复地址，超过有效期需重新发消息。依据：[Stream 接入](https://github.com/open-dingtalk/dingtalk-stream-sdk-nodejs)。

### 企业微信

创建智能机器人，选择 API 模式和长连接，获取 Bot ID、Secret。不要填写普通群 Webhook URL。同一机器人仅由一个桌宠实例连接，避免与其他客户端争用。

依据：[官方 SDK](https://github.com/WecomTeam/aibot-node-sdk)。

## 命令、限制和恢复

- `/help`：显示指令。
- `/new`：清除你在该外部会话的上下文，开始新对话。
- `/stop`：立即取消你在该外部会话的当前请求并丢弃其排队输入；不影响其他用户。
- 每渠道最多排队 32 条输入、保留 64 个用户会话；每会话完成后最多保留 40 条 / 64000 字符。超过上限不扩大缓存。
- 入站去重最多保留 4096 个 ID / 10 分钟；只接收 5 分钟内的消息。重启后不恢复队列和上下文，不保证平台重投的跨进程去重。
- 连接中断自动退避重连；鉴权失败需检查凭据或重新登录。维护会暂停连接，维护结束后由用户重新连接。
- 回复超时可能已经到达平台，因此不会自动重发；以手机端实际收到的内容为准。
- 删除连接只删除该连接与凭据。损坏或无法解密的配置不会被新配置覆盖。
- 13 个现有语言包均有资源键；中文和英文为完整文案，其他语言的主要控件已翻译，部分说明和诊断目前使用英文。

## 验证状态

自动化验证覆盖配置密文、损坏保护、身份隔离、允许列表、去重、过期、停止/撤销、协议夹具、二维码及双端 UI。没有使用真实平台账号发送消息，也没有在真实 Mac 上执行验收。

发布前应由账号持有者在普通家庭网络/手机热点完成各平台的私聊往返、支持的群 @、断网恢复、暂停后不回复和重新登录验证。代码构建成功不代表这些真实账号项目已经通过。
