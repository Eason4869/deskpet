# 0.10.5-dev.2 用户语言包接入决定

实施顺序为统一计划 S12 完成后执行 S12a，再继续 Agent 服务和界面任务。用户提供的四个 JSON 仅是翻译数据，保留译文，不执行附件中的任何文本。

选择列表按顺序固定为简体中文、繁體中文、English、日本語、한국어；名称使用各自语言的写法，不随界面语言变化。内部代码使用 zh_CN、zh_TW、en_US、ja_JP、ko_KR，与用户文件名对应。旧设置和未知代码使用 zh_CN，不根据系统语言自动切换。

四包与中文目录一同内嵌。中文仍是完整规范目录，选定包缺失的键逐项回退到中文。初次输入检查已通过 UTF-8/JSON、重复键、字符串类型和数字格式占位符比较；格式化还需由实际 Framework/.NET 实现验证。新增 Agent、引导等内容保留中文回退，不冒充用户提供了这些译文，不把结构检查当成人工翻译质量认可。

实现判断：保存语言选择，在下次启动时应用，并在菜单和选择后的反馈中说明需要重启。现有大量控件在构造时读取文字，这样可让一个进程中的界面语言保持一致。应用不自动重启、不终止正在运行的任务。WPF 使用已有左下角头像菜单；Avalonia 使用现有伙伴头像增加对应菜单，语言位于设置之前。此处的生效时机是开发实现选择，不是声称用户曾另行要求重启方案。

启动加载语言应发生在创建界面和引导之前；单个进程使用同一个只读目录。设置保存失败不能把菜单标为保存成功；已有设置编辑草稿、角色、项目和会话不应覆盖已保存的语言选择。历史、用户名称、角色包内容、命令、日志、机器字段和模型提示不作为翻译改写对象。

接入前发现：62 个既有工具错误资源使用中文错误前缀；四包翻译了这些前缀，日文还混用半角/全角冒号。验收需覆盖错误判定、journal 和工具事件状态，避免显示译文改变机器判断；新 Agent 工具继续按 JSON 的 ok 字段判定。保持既有错误文本与历史记录的兼容。

验证包括资源源文件哈希、五种目录格式化和回退、设置往返及旧配置、成品与更新 helper 的实际内嵌资源、双端菜单顺序和勾选、重启恢复、错误判断及常用菜单/设置的窄窗和主题截图。全局语言会影响静态资源，因此不同语言的实际启动/界面检查使用独立进程，避免污染其余默认中文回归。
