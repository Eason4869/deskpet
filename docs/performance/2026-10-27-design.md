## 设置生命周期设计

伙伴初始页仍保留现有控件与布局；AI、Work、Quiet、About、IM 首次路由激活时创建一次，之后复用。使用 SettingsPage 内具体的 Ensure 方法集中构造与事件挂接，避免为六个固定类别新增通用生命周期框架。对象为 null 表示尚未创建；未创建不脏、无需刷新与释放。Dispose 幂等且不创建任何对象。

AI/Quiet 的二级 SelectionChanged 在创建时注册。RestoreNavigation 必须先确保目标类别存在，再选其二级页；SelectedSecondarySection 在未创建时安全返回默认值。正常选页、相同页重复进入、深链接使用相同的激活入口，避免漏掉刷新或重复构造。

后台 RefreshState 不再更新隐藏的 Work/Quiet 页；重新激活时刷新最新已提交状态，但所有刷新都遵守已有 HasUnsavedChanges 保护。RestoreDefaultPreferences 是明确操作，允许把恢复结果同步到已存在页，仍不创建未访问页。伙伴基本开关暂保留原有刷新，后续按采样结果再细分。

ConnectionSettingsPanel 当前每次 ShowSection 都拆旧 ScrollViewer 再包一个新 ScrollViewer：改为每个实际访问的 AI 子页保存一个滚动容器，切换复用控件和滚动位置。AI 编辑器本身本轮仍按现有依赖一起构造，后续单列其真正的二级懒创建，避免同时改坏跨 Provider 校验和语音草稿保存。

Avalonia 保留自己的 Control、资源 pin 与 Dispose。页面工厂与结果缓存分开；只释放实际创建的编辑器。恢复默认只重建已创建且可重建的 Behavior/Storage，不提前构造它们；正在编辑的 Provider/IM 页保持原有保存语义。

## 测量与限制

第二批补充：AI 已按 text/asr/speech/live/image 分开构造，直接路由以目标 section 初始化，避免先构造 text。保存先读完并校验所有已访问 Provider 列表，再应用；未访问的服务保留当前已提交值。此处不承诺跨图像保存与历史语音草稿的全局原子事务，原有边界保持。

Provider 草稿基线改为既有 ServiceProviderSettings.Copy，仅克隆所需连接/模型数据，不保留整个 PetSettings 的全局指令、角色、其他配置。两端以受控弱引用回归验证无关指令文本的可回收性；该诊断中的 GC 不参与性能测量。

普通偏好保存第一步采用 UI-owned dirty scheduler：250ms trailing debounce，指针拖动开始 Suspend（保留 dirty），结束 Resume；即便已有上一笔 pending，新拖动也不触发 timer 写盘。每次预览都标记 dirty，以保证拖动中明确保存/退出仍能识别未落盘值。显式保存读取当前 Settings，一并清除 pending；失败保留 dirty，不无界重试，退出失败取消关闭。维护继续使用既有 deferred 保存机制。该步骤没有排队完整快照、没有并行后台写 Store，最终一次 durable write 仍同步；全套字段补丁/异步写入协议尚未完成。

缩放只做几何与图像更新，将同周期的原生窗口位置调整合并到一个 Loaded 回调；以第一笔修改前的底边为锚，使用最新尺寸，保存前先完成待处理几何，减少原先每次缩放触发的全量 ApplySettings 和重复位置提交。

新增 SettingsPerformanceTests：使用隔离目录、无凭据、不启用热键、自动更新或网络服务。`--measure` 在同进程创建 10 份新设置页并测构造/首次 render callback，另记录 30 次伙伴/AI 切换。计时为单调时钟；报告样本数、中位数、P95、最大值、末尾 Private Bytes/Working Set。禁止强制 GC。

这个首批工具测量设置路径，不等同于完整应用冷启动、OS 真正呈现或输入延迟。10 个实例包含 JIT/缓存和自然 GC 的影响；末尾内存只是进程快照，不足以证明泄漏或稳定保留堆节省。完整新进程、典型/压力数据与跨平台实机仍是后续基线任务。

先在未修改产品代码时运行同一工具取得基线，再验证生命周期测试在旧实现上失败，改动后用相同数据重跑。对性能数字只报告实测结果，不预先承诺百分比。

## 后续阶段的补全设计

### 普通偏好与持久化

先统计缩放、音量、位置等入口写盘次数，再拆预览/提交。指针拖动只预览、结束提交；键盘/离散操作末次事件后 250ms 合并。普通偏好使用不可变字段补丁，不能把旧完整 PetSettings 异步排队。所有 SettingsStore 写入必须建立统一提交顺序，包括 Provider、语言、引导、恢复默认和维护；未完成该审计前不引入后台写盘。

维护：停止接收相关修改 → 排空 → 获取维护门禁 → 执行 → 重建基准/epoch → 恢复。退出失败则保留 pending、取消关闭并允许用户重试，不无界重试、不吞错退出。强杀可能丢失整段未提交交互，不能说只丢 250ms。该阶段以确定性并发测试单独交付。

### 启动与壳

对配置读取、恢复、角色目录、首帧、服务启动分别计时。以 trace 决定哪些工作延后，先维护恢复/身份/校验顺序，再研究无需完整聊天视图即可打开设置的应用壳。后台准备使用 generation 与取消；界面控件始终在其所属 UI 线程操作。

### 图像/动画资源

记录解码耗时、重复解码、像素/掩码预算、活跃 pin 和命中率。把确认的同步解码移出渲染热路径；同资源合并加载。WPF 冻结位图与托管回收、Avalonia 原生 Bitmap Dispose 各自适配，显示中的资源持有 lease。未就绪时显示合法旧帧，动作计时不能提前流失。首轮不降分辨率/帧数，不直接二值化 AlphaAt。

### 历史、轮询与代码整理

历史已有 50 轮显示窗口，但重载仍可能全量分组/重建；有热点证据后先做当前会话索引和增量追加，再单独评估可变高度虚拟化。保留 Markdown/图片、复制、滚动锚点、消息重试及切换会话语义。

轮询先分为渲染推进、输入/窗口、低频维护、事件状态；消除未变化状态的重复枚举，而非整体降低帧率。绑定反射只在测得成本后缓存；语言 revision 和数据 revision 分开，保留用户编辑保护。

删除清单需列出引用、字符串/反射入口、Build.ps1、共享项目链接及兼容约束。只删已等价替代或证实无用的代码；移动 partial 不等于解耦。
