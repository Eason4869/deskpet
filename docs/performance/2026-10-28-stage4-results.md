# AI 冷构造与显式保存优化

日期：2026-10-28。起点为本地 dev.2 优化分支的 `b32cea6`，发行目标为用户指定的 `0.11.3-dev.1`。

## 冷构造证据

加入 opt-in 的 `SettingsConstructionTrace`，只记录代码边界与耗时，不记录配置、地址或凭据。初始独立构造约 1192ms；其中 Provider rail 约 140ms、详情控件约 323ms、连接字段约 370ms。空 Provider 和已折叠详情仍在提前构建，是本批移除的实际工作。

- 空 Provider 保留 rail 与引导提示，实际需要编辑时才创建详情。
- 合法已保存连接按展开创建字段；预览、读取和脏状态判断使用独立数据，不为查询构建 UI。无效连接仍立即展示需要修正的字段。
- Provider item 样式按实际使用创建；保留上一批模型编辑弹窗懒创建与滚动容器复用。
- Guide 请求字段时展开并创建；未访问页面不脏，已存在草稿不被外部刷新覆盖。

同日对照从 `b32cea6` 提取原始源码，使用相同测试驱动、资源与编译选项单独构建控制程序。测量时没有并行构建或其他 UI 测试，均为隔离配置，无强制 GC。

计时使用 10 个新设置实例、30 次伙伴/文字页切换，render callback 是布局/渲染代理，不是 OS 呈现或输入延迟。末尾 Private Bytes 为 367075328、Working Set 为 496672768；这些单点不代表稳定保留内存或整机节省比例。原始记录在忽略目录 `work/performance/stage4-control-*`。

## 显式保存协议

WPF 的 AI、保存连接后发现模型、语音/Live 测试前保存、图片保存/测试、全局 Work 与提示词、MCP、人设、网络、语言、模型选择实际 UI 入口使用 await。后台候选独占规范化、序列化、刷盘与原子替换；成功后才发布相应运行字段和保存基线。失败保留原运行配置、磁盘配置与编辑器草稿。

同一路径的 publication lease 覆盖提交与 UI 发布；其他显式编辑器在提交前拒绝重叠操作，同一保存重复点击复用在途事务。运行期间发生的其他设置修改进入 deferred 路径，提交前合并；仅确认同一份已提交的普通偏好补丁，不丢弃更新的 held 拖动。公开同步兼容入口继续供现有 SettingsWindow 自动化使用，参与同一提交/错误提示修订协议。删除不再使用的私有 MCP、图片同步入口。

语言保存保留既有 JSON 未知字段，先准备语言并后台持久化，再在 Dispatcher 刷新。嵌入宿主尚未进入 Application.Run 的调用也建立正确 DispatcherSynchronizationContext。选择窗口等待真实保存结果，失败保持打开。

维护登记排空完整显式事务，含 UI 发布；恢复默认在提交与发布期间阻止旧普通保存。退出停止新请求、等待显式和普通保存，再持久化最终配置，失败取消关闭并恢复窗口。后台保存不能把“已提交到磁盘”与“已发布到运行设置”混为同一时点。

## 项目配置与会话准入

项目级 Work 写入独立 `projects.json`，不排队旧完整目录。后台持有原有 `.write.lock`，严格读取最新目录，仅合并真正变化的标量配置字段，保留其他会话与侧栏数据。

提交后至 UI 发布前，同路径的短期字段 fence 防止普通同步目录保存把旧配置写回；明确发生了更晚修改的字段保留其新值。发布保留现有 ProjectDefinition 引用；活跃记录在完成时移除。无效目录拒绝覆盖，失败不发布、不遗留 fence，临时文件按唯一所有权清理。

复用 DataMaintenanceGate 为每个项目建立弱引用准入槽：配置事务期间阻止同项目队列接收、直接会话启动、草稿提交准备与新工作区创建。先前已在运行的请求使修改失败，不自动取消任务；提交及 FollowProject 完成后恢复准入。独立槽不阻止其他项目工作，不替换应用数据维护门禁。

## 审查回归

全局阶段独立审查的 1 个 P1、3 个 P2 均先失败复现，再修复：人设迟到回调清空另一会话、向导文字测试保存阶段重入、关闭后的迟到推进、同步兼容失败提示被旧普通回调清除。人设清理同时检查原会话、原 PersonaId、原角色和空闲状态。向导在首次 await 前登记测试取消与 lesson，关闭推进时等待保存结束。

项目模块另做独立审查，两个 P2 均完成 RED→GREEN：后台失败不能回滚未由本事务修改的 live 项目字段；保存期间必须阻止同项目新请求。没有通过重复审查代替失败复现。
