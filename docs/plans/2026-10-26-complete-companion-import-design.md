## 方案选择

1. **选择：保留五个完整包，统一导入政策并完整登记所有外观。** 一次导入一个角色即可获得其全部资源，与用户交付方式一致。
2. 拆成默认与节日增量包：可减小单次下载，但需要额外依赖、版本组合和缺件恢复机制；本次不采用。
3. 仅压缩 ZIP 或降低帧数：不能解决解压容量、条目数量和漏装目录问题；降低动画质量也违背已确认需求，不采用。

## 统一资源政策

新增可信的应用内政策 `assets/official/companion-package-policy.json`，由共享 C# 读取器 `CompanionPackagePolicy` 与 Python 打包工具使用。该政策随应用构建嵌入，不能由导入 ZIP、用户目录或网络元数据提高上限。Build.ps1 和 DeskPet.Core.csproj 使用同一逻辑资源名。

| 项目 | 精确上限 / 规则 |
|---|---|
| 单完整包 ZIP 实际字节 | 536870912（512 MiB） |
| 单完整包解压/安装/收据文件累计 | 536870912（512 MiB），分别独立检查 |
| ZIP 条目 | 1024，包含目录；1025 拒绝 |
| 单 PNG 文件 | 26214400（25 MiB），保留 |
| 根 pet.json | 65536（64 KiB），保留 |
| 其他 JSON | 1048576（1 MiB），保留 |
| 文本说明 | 本地路径保留 1048576（1 MiB）；官方路径保留 65536（64 KiB），不收紧旧本地包 |
| 单外观引用的不同图片总量 | 268435456（256 MiB）；默认与各节日分别累计 |
| 单默认 v2 外观总动作帧 | 1024，保留；不跨 11 套外观累加 |
| 节日外观数量 | 每角色最多 32 套；本批必须恰好 10 套 |
| 图片几何与内容 | 保留现有分辨率、帧数、RGBA、透明度和有效像素约束 |

使用 long/checked 累计；上限值允许，超出 1 字节拒绝。跨引用仅对同一规范路径去重，不能借别名规避统计。压缩和解压上限同时生效，重新压缩不是绕过方式。一般 v1/v2 单皮肤的既有兼容能力保留；完整包新政策不要误套到其他附件或应用更新包。

## 完整导入流程与接口

新增共享 `CompanionPackageInventory`：解析根 pet.json、可选 companions.json、holidays/catalog.json、每套 outfit.json，并枚举全部实际引用的 PNG。旧默认包没有 holidays 时继续支持；catalog 存在但缺定义、缺图、身份冲突或外观不完整时整包拒绝，不能悄悄丢掉坏皮肤后显示成功。

库存结果包含：包 ID、声明版本、内容摘要、默认引用、节日引用、全部引用、各外观字节数和节日 catalog 根。全部引用必须包含元数据本身和允许随包安装的说明文件，并在同一包根下解析；禁止路径穿越、链接、重复路径、大小写碰撞、设备名及跨根引用。拒绝未引用 PNG、可执行文件和保留收据路径；允许有界的 README/LICENSE。ZIP 与目录导入使用相同库存规则。完整库存仅接入完整角色包分支；普通无包 ID 的旧 v1/v2 单皮肤继续走原有兼容入口。

两端复用现有入口，改为：预检查容量与条目 → 临时解压 → 完整库存与结构校验 → 逐图原生解码校验 → 安装到新不可变目录 → 在最终目录再次打开检查 → 发布指针 → 刷新角色/衣橱和渲染源代次。

安装校验不能仅验证根 pet.json。不改写原始图集；默认图像保持交付字节。新节日图集也不重新生成。缓存和来源绑定最终安装目录，不能绑定随后删除的解压目录。

本地声明 `id=e-bao` 不构成官方身份认证。保留现有 `custom-pack:` 与 `official:` 来源区分、身份映射、同名角色行为和用户数据归属；用独立的“服装角色 ID + 包来源”绑定本地节日库，不能为了使其换装而授予官方信任或覆盖官方目录。

资源来源和服饰持久状态必须同时隔离。新增稳定状态键 `official:{characterId}` / `custom-pack:{packageId}`，分别保存 Enabled、收藏解锁、PreferredOutfitId、活动手动覆盖；不以每次换装生成的 SourceKey 作为持久键。同名本地与官方角色不共享上述状态。沿用各来源内的既有解锁规则，不因导入包而赠送另一来源的收藏。

迁移现有仅按 CharacterId 的状态时，升级节日状态 schema 并先备份：若当前注册表能证明旧记录只有一个既有来源，迁移到该来源；有歧义或无法证明时，旧记录保留在官方键，本地来源初始化为默认设置，同时保留旧文件备份和迁移记录。迁移仅执行一次，不在导入/换装时反复复制。用户聊天、关系、身份映射及其他个人数据不迁移到新角色。此归属规则是本计划的兼容决策，必须通过两来源同 ID 的设置和重启测试。

同 ID 同内容重复导入不产生重复角色；同 ID 不同内容在校验成功后替换该来源的资源。当前交接版本字段较旧，不按字符串版本强行忽略新内容，也不静默覆盖更新的线上官方版本；本地包按内容摘要识别修订，官方包仍遵循其版本与摘要协议。

更新保留昵称、人设、音色、聊天、关系、位置、收藏、手动选择等现有个人设置。未发表成功的暂存资源可以清理；仍被窗口读取的旧版本不得立刻删除。提交点之前的取消、磁盘满、文件锁、权限错误及损坏资源均须保留原有效指针和角色。发布指针是提交点；提交后的取消不删除已安装有效版本，刷新中断由重启/重试恢复。身份映射和显示状态的写入要有明确恢复顺序，不允许先修改旧角色设置再开始验证新包。

## 外观发现、日历和动作

每个已安装角色都能发现默认 + 10 节日；“安装了资源”“已收藏解锁”“当前正在穿着”是不同状态。沿用正式解锁规则；开发验收用独立数据目录准备全解锁，不改系统时间或正式用户数据。

复用日历既有农历与时区规则，补齐缺失的 2/14 情人节；春节、元宵、端午、中秋、七夕不可写死公历，清明使用已验证节气数据；国庆必须为中华人民共和国 10/1–10/7，10/8 不触发。其余已有节日范围不扩大。节日重叠沿用最终基线的确定性优先级，测试中记录并锁定。无数据年份不得猜测日期，保留默认外观和现有提示/降级机制。

动作读取图集的帧数、fps、loop、variant 与已有 offset，不添加新的全身左右摇摆/缩放。19 个 default 动作 + 8 个 alternate，E包和咕嘎另有 jumping alternate；另有 gaze、easter_egg、preview。默认皮肤按原清单验证，不要求改造成统一帧数。

- 待机保留眨眼和轻微自然呼吸，人物大小与站位稳定；咕嘎待机无频繁歪头。
- 挥手实际手臂运动；跑步实际步态；跳跃依次展示预蹲、起跳、腾空、接地、恢复。
- 新节日 jumping 在帧内已有竖直位移，该 clip 播放时不再叠加窗口跳跃位移；默认皮肤保留原逻辑。真实拖拽落下的窗口物理继续生效。
- 摸头映射 petting，戳身体映射 poked，使用不同反应、完整播放并恢复；命中区域基于当前帧与显示缩放，不能戳衣饰透明区误触身体。
- 打盹、等待、工作、阅读、喂食、提起、落地、招牌动作、彩蛋、切换变体均按定义播放。中断和恢复不能跨角色、跨皮肤泄漏。
- 五星红旗和普通月饼纹样沿用已验收资源；UI 中不得出现“小北”。

## 内存、加载与磁盘

元数据可完整枚举，渲染只加载正在使用的外观和动作。安装验证需逐图解码后释放，不把十套动作加入运行缓存。复用已有缓存，增加字节计量：新节日渲染资源的持有预算为每个宠物窗口 256 MiB，合计图像像素、分离帧和 alpha mask；不同窗口分别记录，不能把此数称为整进程峰值上限。

缓存键包含包来源、内容修订/源代次、外观、动作变体、几何；新修订不能命中旧图。同一 clip 多次命中不重复解码。当前可见帧和转换中帧需固定到绘制完成，禁止淘汰后释放正在使用的 Avalonia Bitmap。换装、切角色、修复和关窗释放过期资源，WPF 引用也需解除。

性能验收：55 外观逐一切换，连续 30 轮；记录缓存字节/计数、解码次数、私有内存/RSS、线程、句柄、导入时间和首次出帧。预热后最后 10 轮缓存不随历史外观数累计，预算满足；释放并等待稳定后最后 10 轮内存波动增长目标不超过 32 MiB，超出必须调查或有可复现的非泄漏证据。该目标是拟定验收线，不是当前测量结果。用户操作/播放时不能在 UI 线程同步解码整个包。

磁盘按单角色顺序导入；本批五包解压合计约 1.43 GiB。预检空间包含 ZIP 暂存（如需复制）、解压暂存、新安装副本、保留旧版及 64 MiB 余量；不得只拿 ZIP 大小估算。低空间提前报错，并保留底层写入失败处理。

## 官方发布适配（后续独立步骤）

先完成本地导入与原生验证，再考虑官方资源发布。使用首次包含本导入能力的应用发行版本作为新包的最低兼容版本；包发行版本必须高于已发布的对应官方版本，并由发行流程确定，不能复用交接资料中的旧 0.10.5-dev.3 来伪装兼容。

## 验收与完成定义
