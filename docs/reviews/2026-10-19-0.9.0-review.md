## 本轮已修复

### 1. P2：输入网址后光标落在最后一个字符之前

根因：粘贴后的裸网址被转换为 `[显示地址](目标地址)`，重建文档时仍用转换前的源文本偏移恢复光标，导致可见位置前移。

修复：在解析树和 WPF 文档中保留自动链接身份，自动链接仍序列化为用户输入的裸地址；显式 Markdown 链接保留独立标签和目标。自动链接编辑时重新解析，避免修改域名后仍跳转到旧地址。网页图标取消独立命中与焦点，统一使用所属链接的交互入口。

涉及：`src/MarkdownContent.cs`、`src/MarkdownDocument.cs`、`src/MarkdownEditor.cs`。

回归覆盖完整聊天和快速对话：末尾粘贴、中部粘贴、继续输入、修改域名，以及显式 Markdown 标签编辑不改变目标。

### 2. P2：处理中图标显示不完整

根因：`UiIcons.Image` 默认尺寸为 18×18，但过程图标容器固定为 14×14，子控件超出布局范围。

修复：显式按容器宽高缩放矢量图标，保留原有布局和间距。读取、写入、命令、搜索和联网五类图标均检查实际 WPF 布局边界。

涉及：`src/ChatMessageView.cs:196`。

### 3. P2：未发送图片无法点击预览

根因：已发送图片绑定了预览事件，草稿附件仅绘制缩略图和移除按钮，没有绑定预览入口。

修复：草稿图片接入同窗口图片预览，支持点击与 Enter／Space；预览保留草稿和附件，移除按钮继续独立处理事件。完整聊天、快速对话均有回归。

涉及：`src/ConversationComposer.cs:311`。

## 初审确认的问题（本轮已修复）

以下根因与复现描述针对初审基线。后续已经按计划修复：终端逐条人工确认；MCP 深复制并保留完整根 schema；业务／请求错误返回有界原文并保留连接，HTTP 与 stdio 的取消分别处理。新增回归及最终验证见文末。

### 4. P1：破坏性终端命令可绕过敏感操作审批

位置：`src/AgentKernel/AgentAccessPolicy.cs:56`、`src/AgentKernel/AgentAccessPolicy.cs:73`。

根因：通过命令字符串黑名单判断风险，未命中的沙箱命令直接允许。PowerShell 内置别名及直接调用 .NET 文件 API 均可绕过这一判断。

隔离复现：在“请求批准”＋沙箱＋终端启用条件下，提供始终拒绝的审批回调，执行删除自建 fixture 文件的 `ri -LiteralPath (Join-Path $PWD.ProviderPath 'victim.txt') -Force`；实际退出码为 0、文件被删除、审批回调次数为 0。

影响边界：没有证明或声称 AppContainer 逃逸；问题是项目可写范围内的破坏性操作绕过敏感确认，而且终端删除不经过文件工具的备份流程。

证据：`work/review-0.9.0/work/review-agent/terminal-schema.log` 第 1 行；夹具为同目录 `ReviewProbe.cs`。

### 5. P2：合法 MCP 参数 schema 被转换为无效结构

位置：`src/AgentKernel/McpToolAdapter.cs:146`、`src/AgentToolCatalog.cs:52`。

复现一：合法无参数 schema `{"type":"object"}` 被输出为 `properties:{"type":"object"}`，把根类型字段误当成参数字段。

复现二：带 `$defs` 和 `$ref` 的 schema 被拆解后丢失根级 `$defs`，输出仍保留对已不存在定义的引用。

影响：注册这类 MCP 工具后，模型服务可能拒绝整个工具列表，导致工作请求失败。

证据：`work/review-0.9.0/work/review-agent/terminal-schema.log` 第 3 行，已经核对实际生成的 OpenAI 工具参数。

### 6. P2：一次 MCP 工具业务错误导致服务器断连

位置：`src/AgentKernel/McpToolAdapter.cs:60`、`src/AgentKernel/McpConnectionManager.cs:59`。

根因：标准工具结果 `isError:true` 被转成泛化异常，连接管理器又对所有调用异常执行 Disconnect，丢弃该服务器的工具。

复现：通过真实 `McpHttpTransport` 配合进程内 HTTP handler 返回业务错误，连接状态从 `connected` 变成 `disconnected`，已连接 transport 数量变为 0。业务错误正文也未保留给模型修正请求。

证据：`work/review-0.9.0/work/review-agent/mcp-business-error.log`；未使用真实第三方 MCP 账号或服务。

## 实施顺序与发布计划

前三项已按以下顺序实施并验证。下一补丁可使用 **0.9.1**；本轮没有修改版本号、提交、推送或发布，正式发布验收单独进行。

1. **先修终端审批（P1）。** 对无法可靠证明安全的任意终端代码进入审批，避免把字符串黑名单当作允许执行的依据。回归应涵盖 PowerShell 别名、模块限定命令、.NET 文件 API、组合命令、取消与人工拒绝，并核对拒绝后文件未改变、进程未启动。保留 AppContainer 隔离。
2. **修复 MCP schema（P2）。** 保留完整输入 schema；正确处理缺省 properties、嵌套引用、`$defs` 和组合约束。对模型协议不支持的结构提前给出明确错误。回归应检查最终发出的 OpenAI／Anthropic 工具结构，而不只检查内部 DTO。
3. **修复 MCP 错误生命周期（P2）。** 将工具业务失败、协议错误、传输失效和用户取消分开处理；业务错误保留有界原文，允许模型修正后继续调用。验证业务失败后连接仍在、第二次调用可成功；真实连接失效仍按策略清理。
4. **补丁发布验收。** 合并本文三项界面修复和后续修复，重跑 Windows 相关回归、配置引导、更新兼容和安装／便携包验证；共享 schema 变更另跑共享核心及 Mac 测试。最终版本验收完成后再更新 CHANGELOG、版本和发布附件。

## 后续修复与最终验证

三个 Agent／MCP 问题已完成修复，并分别保留了先失败后通过的回归记录：

1. **终端审批。** Ask／Auto 下的任意 Agent 终端代码进入逐条人工确认，不再从字符串黑名单的未命中推导允许执行。新增回归涵盖 PowerShell 别名、模块限定命令、.NET 删除、动态命令名、组合语句、人工拒绝和审批中取消；拒绝后文件保持原值、没有执行结果。另验证人工允许后仅执行一次且真实使用 AppContainer，Full 与 Legacy 保留原有权限边界。
2. **MCP schema。** 单独保存完整根 schema 的深复制快照，保留 `$defs`、`$ref`、组合约束和 `additionalProperties`；缺省 properties 使用空对象。注册时明确拒绝根类型、properties 或 required 的明显无效结构。最终 OpenAI／Anthropic 序列化结构和嵌套定义的防篡改快照均有回归。
3. **MCP 错误与取消。** 标准工具业务失败及 JSON-RPC 请求错误返回有界原文，保留连接，让模型修正后重试；审计与工具结果仍标为错误。HTTP 用户取消保留会话；stdio 取消会清理可能失去同步的流与自有进程。真实解析失败或连接失效继续断开。覆盖实际 HTTP transport、内存 stdio 协议及真实 stdio 子进程。
