# 本地消息渠道设计

基线：main / v0.11.1，bec057b0dd90316be4f3be635b0e5f00ef1e8748。
用户已要求基于该版本开发；沿用已确认的自建机器人、本地直连、无公网 IP 和无开发者服务器约束。

## 架构选择

比较原生 C#、打包 Node 辅助进程、外部 AstrBot 桥接。采用原生 C#，避免新运行时与进程维护；代价是维护平台协议与飞书 protobuf 帧。协议实现以当前官方 SDK 为依据，不引入托管中转、Webhook、公网端口、用户安装框架或任意自定义网络端点。

共享核心提供 ImChannelProfile / 加密配置存储 / ImChannelManager / 平台适配器 / 独立会话路由。UI 仅负责配置、启动暂停、诊断和绑定。两个宿主创建同一服务，使用已有模型 API、凭据保护和维护闸门。

## 产品范围

- QQ 官方机器人：App ID / Secret，主动 WebSocket，私聊与群 @ 文字回复。
- 微信 ClawBot：二维码授权，长轮询；只开放私聊文字。
- 飞书企业自建机器人：App ID / Secret，长连接收消息与 REST 回复。
- 钉钉内部应用：Client ID / Secret，Stream 连接，短期回复 URL。
- 企业微信智能机器人：Bot ID / Secret，官方 WebSocket 收发。
- 首版不开放远程 Agent 工具、附件、语音和跨平台转发；非文字输入给出明确提示。
- 模型配置复用现有设置，绑定时冻结人格；切换桌面宠物不改变既有机器人绑定。
- 默认允许列表为空时拒绝所有模型调用；UI 显示最近发送者 ID，用户在本机明确添加后才能对话。群聊同时检查群和发送者；只处理实际 @。
- 渠道、机器人、外部会话、发送者共同确定独立上下文；永不加载桌面私聊历史。
- /help、/new、/stop 由宿主确定性解析；不会把远程消息升级成系统指令。

## 运行与恢复

进程级互斥锁保证同一数据目录的渠道只由一个宿主处理；每个启用渠道有一条生命周期任务。断网指数退避；鉴权失败显示需重新配置；UI 不把打开 TCP 连接当鉴权成功。

每条外部消息在短回调内进行验证、去重与有界入队，模型生成不阻塞平台接收/ACK。单渠道队列有界、同会话串行；重复 message ID 不重复生成，发送超时标记不确定，禁止盲目重发。无 ID 或过期事件拒绝；最长排队年龄 5 分钟。关闭/暂停取消请求并等待任务退出，再释放网络资源。

持久化配置包括版本、非明文密文载荷和平台凭据；原子替换，损坏/解密失败禁止覆盖。仅配置自动启动显式启用的渠道。消息上下文仅在内存中保留有界窗口，退出即清除；不承诺离线补发或全天在线。

维护闸门启用时停止接收处理；模型请求持有活动租约，清理/恢复必须等待或取消。退出不遗留连接。配置和上下文不记录原始平台 payload、token、二维码登录内容和用户正文到日志。

## 网络与协议

HTTPS/WSS、平台域名白名单、禁止凭据跨域重定向，禁用自动重定向；响应/帧大小上限 1 MiB，30 秒连接/请求超时（微信轮询 45 秒），模型超时沿用用户配置并受取消约束。非平台 URL 不接受。QQ token 刷新、心跳、断连重鉴权；飞书 protobuf 与分片；钉钉 ACK / 心跳；企微认证回执；微信轮询游标和 context_token 均独立处理。客户端不可伪造 OpenClaw 身份，使用 DeskPet 版本标识。

## 设置与视觉

Windows 和 Avalonia 设置均新增末尾导航项“消息渠道”，保持旧导航索引稳定。页面沿用现有浅/深主题、字号、24px 页面边距和控件风格。上方标题与在线条件说明，中部已配置列表，下方编辑区域：平台、名称、凭据、绑定人格、允许的发送者/群组。微信显示登录二维码内容与系统浏览器入口。底部“保存”“连接”“暂停”“删除”动作，删除仅删除连接与凭据；状态显示认证中、已连接、重连、已暂停、失败、最近发送者与脱敏错误码。密钥默认隐藏且不从 UI 复制到普通日志。

所有文案走 TextResources，13 个现有语言包有键，支持现有即时语言切换且保留编辑草稿。未验证的平台不显示已验证标签。

## 验证

单元/集成验证：凭据密文、损坏配置保护、允许列表、群 @、会话隔离、去重、队列上限、取消、过期、网络域名校验、五种官方协议夹具、飞书 protobuf 分片和回复关联。
构建 Windows .NET Framework 与 .NET 10 核心/Avalonia；添加双端导航与 UI 检查，更新 README/CHANGELOG/接入说明。
真实平台验收需要用户自己的机器人/扫码，不在聊天中索要密钥。自动测试通过与真实账号通过分别报告；本次不默认推送、合并或发布。

## 审查补充

每渠道队列 32 条、会话 64 个、每会话 40 条/64000 字符，去重 4096 条/10 分钟，飞书分片最多 32 个消息、每消息 1 MiB、30 秒有效期。满额拒绝，不创建额外任务。/stop 在允许列表验证后直接取消当前作用域并使其排队消息失效。维护沿用活动任务时报告忙的语义，维护进入时停止渠道；维护后用户显式重新连接。所有编辑/删除先停止旧代次并等待退出，再原子保存；保存失败不启用新配置。
