# 推送与发布前必检：配置引导

每次修改完成后，推送 GitHub 仓库之前必须核对当前构建的“配置引导”；正式发布前也必须确认该检查针对最终待发布版本完成。历史版本的通过记录不能代替本次检查。此步骤无需在每次编辑后立即运行，应安排在推送／发布验收阶段。

- 从首次启动和设置页入口检查引导，核对步骤说明、目标控件、高亮及可操作区域与当前 UI 一致。
- 核对拖动、单击、双击和聊天预览，以及 AI 服务配置、模型列表与显示名；检查必填校验和当前步骤独立保存。
- 核对返回、继续、稍后、跳过、退出及重开后恢复；退出引导后正常控件应恢复可用。
- 运行相关引导回归，并检查实际窗口。记录构建、结果和证据；原生鼠标受限时明确标注，模拟手势通过不能写成原生交互已通过。
- 有失败项或未完成项时，先解决或明确交由用户验收，不能把旧版通过记录作为推送／正式发布依据。

## 主动问候与菜单

问候使用本地台词，不请求模型、打开麦克风或写入聊天历史。计时测试先复现到期前结束对话/全屏后没有重新等待完整间隔，再验证恢复节流。真实 WPF 全屏窗口先复现已显示的气泡仍覆盖全屏，再验证一秒内收起；预览不会抢输入焦点。

菜单测试使用独立进程的 `WM_MOUSEACTIVATE = MA_NOACTIVATE` 空白窗口，先复现点击外部空白后菜单仍开着，再验证修复。没有依赖全局鼠标钩子。

## 自动更新

更新协调器以隔离版本源测试自动检查、下载和取消；模型、密钥、人格等未保存草稿跨设置页面仍阻止重启。后台更新通过不激活的桌宠气泡显示五秒倒计时及取消按钮。进入助手交接后暂停新对话和设置编辑，助手确认后再次检查活动；状态变化会写入取消标记，保留当前进程。

实际更新生命周期测试使用两个仅用于测试的旧/新 EXE 和真实生产助手代码。安装版仅替换测试 AppId、互斥锁和开始菜单组；没有修改用户正式安装的注册表、自启或快捷方式，也没有关闭用户正在使用的桌宠。测试覆盖中文空格路径、原目录安装、保留设置和导入外观、便携替换、独立助手等待旧进程并重启新版。

取消交接、无法写入结果回执和损坏包恢复均先复现失败再验证修复。回执写入为尽力执行，不能阻止重新打开已更新或恢复后的程序。ZIP 中的模板说明文件允许正常升级，未知文件、`data`、穿越及重复条目仍拒绝。

`PackagingSmoke` 只在本地独立测试目录生成 ZIP 和安装器以验证源码可构建，没有上传或创建 0.3.2 Release。运行目录中的个人配置、密钥和聊天信息不进入公开源码或运行包。
